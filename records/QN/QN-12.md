# QN-12. Do not attach an annotation extension to a NOT annotation.

## Decision

Do not attach an annotation extension to a NOT annotation.

## Context

An extension narrows the term, so "NOT X has_input(Y)" would claim only that the product does not do X *to Y*. In practice curators have used it to mean "under these conditions X does not happen", which hides a condition inside a negation. That is the reason GO deprecated `independent_of` and `in_absence_of` ([wiki: Annotation Extension Relation:independent of](https://wiki.geneontology.org/index.php/Annotation_Extension_Relation%3Aindependent_of)). The current wiki forbids NOT with extensions ([wiki: Elements of an annotation](https://wiki.geneontology.org/index.php/Elements_of_an_annotation)), and a reply on [go-annotation#2326](https://github.com/geneontology/go-annotation/issues/2326) says this is enforced through error logs. GO's rule registry nevertheless records gorule-0000053 ("NOT annotation should not have extension") as *deprecated, will not be implemented*. The stated reason is that negated extended annotations are logically well-formed ([Drive: Feedback on GO rules (FlyBase copy)](https://drive.google.com/open?id=1AiEBQGA37oyyoFmDYNexYOlDIwqPHnMvAESIVqgjxFM)). We follow the wiki.

## Application

**Example.** A kinase active on substrate A and inactive on substrate B: annotate `enables` GO:0004672 with `has_input`(A). Do not add NOT GO:0004672 `has_input`(B). If inactivity on B matters biologically, say so in a GO-CAM or in prose.
